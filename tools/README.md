# tools/ — перевірка й випуск Кіноперу

Потрібні: Python 3.14 (`py`), `websocket-client`, Chrome. Нічого, крім стандартної бібліотеки. Секретів тут немає (файли віддає GitHub Pages).

## Команди
- `py tools/check.py --quick` — ~30 с: усі вкладки + усі оверлеї (відкрити → «Назад» закриває лише верхній → фокус/inert) у режимі Android Chrome, вихід із застосунку.
- `py tools/check.py` — повний набір (~2 хв): ще й телефон без CloseWatcher (історія), ПК з Esc і кнопкою «назад» миші, Android + Esc, ПК-вкладки.
- `-k <підрядок>` — лише сценарії, чия назва містить підрядок (`-k title`, `-k "stack/"`, можна кілька `-k`). `--list` — показати, що запуститься.
- `--shots` — знімки в `tools/_out/shots` і попіксельне порівняння з `tools/_out/baseline`; `--baseline` — (пере)створити еталон. Постери підмінено сірим, годинник заморожено (13.11.2026 12:00 UTC), анімації вимкнено — знімки детерміновані.
- `py tools/ship.py "<повідомлення>"` — випуск: відмовляє, якщо версія в CHANGELOG не новіша за живу або нічого комітити; `stamp.py` → `check.py --quick` (`--full`) → commit → push → чекає, поки Pages віддасть версію → `LIVE <версія> <хеш>`. `--no-check` — без перевірки, `--dry-run` — усе, крім commit/push.
- Код виходу 0/1. Рядки: `PASS`/`FAIL`, `XFAIL` (відома вада зі списку `XFAIL` у scenarios.py, не ламає прогін), `XPASS` (вада зникла — прибрати з списку).

Типова дрібна правка: правка → `py tools/check.py --quick -k <область>` → версія й запис у CHANGELOG (js/settings.js) → `py tools/ship.py "<що>"`.

## Як додати сценарій (tools/scenarios.py)
- Новий оверлей: рядок у `OVERLAYS` (`open` — JS відкриття, `is_open` — умова, `root` — елемент шару). Для нього автоматично з'являться сценарії в усіх режимах «Назад»; пара шарів — рядок у `STACKS`.
- Довільний: `@scenario('назва', modes=('android','desktop'), app=False)` + `def f(c): ...`. Є `c.eval(js)`, `c.wait(js, секунди)`, `c.snap('мітка')`, `c.close_top()`, `c.assert_(умова, 'що не так')`, `c.b` (Browser з cdp.py: `key`, `back`, `load`). Помилка сторінки (console.error, виняток, CSP) = FAIL автоматично.
- Нова відома вада: `XFAIL['ім\'я[режим]'] = 'причина'`.

## Що в cdp.py
Сервер репо на вільному порту, headless Chrome з тимчасовим профілем (прибирається завжди, навіть при Ctrl+C), мережа вимкнена: постери → сірий PNG, OMDb/TMDB/TVmaze/Google → заглушки (TMDB-картки генеруються), решта зовнішнього блокується. Дані — `tools/fixtures/seed.json` (з лабораторії, вигадані ключі). Режим Android: підмінено UA + `userAgentData`, «Назад» = Esc, який сторінка пропускає до CloseWatcher. Не вмикати `Runtime.enable`/`Network.*` — на Chrome 157 це зависає.

## Чого headless не перевіряє
Справжні жести (свайп-«Назад», свайп шторки), анімації й плавність, клавіатуру телефона, адресний рядок/смугу жестів Android, фактичну поведінку Samsung Internet/iOS. Це для `tools/phone.py` (справжній телефон через adb): `check.py --phone` імпортує його й виконує `phone.SCENARIOS = [(назва, функція_без_аргументів), …]`; нема файлу — чисто пропускає.
